# ECLIPSE ONLINE — แผนเซิร์ฟเวอร์จำลองเกมเอง (Headless Server)

สถานะ ณ N10: ระบบออนไลน์ทำงานแบบ **host-authoritative** — เครื่องของผู้เล่นคนหนึ่ง (Host ของห้องแมพ) เป็นคนจำลองมอนและบอส
เซิร์ฟเวอร์ทำหน้าที่ส่งต่อข้อมูล + ตัดสินเรื่องสำคัญบางส่วน (ห้อง, ปาร์ตี้, รอบดัน, ใครฆ่าบอส, ปลดล็อกดัน, กองของ)

แผนนี้คือการย้าย "การจำลองเกม" ทั้งหมดไปไว้ที่เซิร์ฟเวอร์ เพื่อให้ **โกงไม่ได้** และ **ไม่ขึ้นกับเน็ตของ Host**

---

## 1. ตอนนี้ใครเชื่อใคร (จุดอ่อน)
| เรื่อง | ใครตัดสินตอนนี้ | โกงได้ไหม |
|---|---|---|
| ตำแหน่งผู้เล่น | เครื่องผู้เล่น (เซิร์ฟเวอร์แค่จับวาร์ปเร็วเกิน) | ได้ (speed hack) |
| ดาเมจที่ผู้เล่นทำ | เครื่องผู้เล่น → ส่งให้ Host | ได้ |
| มอน/บอส AI, ดาเมจที่มอนทำ | Host | Host โกงได้ |
| บอสตาย | Host รายงาน → เซิร์ฟเวอร์ให้เครดิต | Host ปลอมได้ (แต่ต้องอยู่ในห้องแมพบอส) |
| EXP / ของดรอป / ทอง | เครื่องผู้เล่นแต่ละคน | ได้ |
| กระเป๋า / เซฟ | เครื่องผู้เล่น (เซฟเก็บบนเซิร์ฟเวอร์ แต่เนื้อหามาจากเครื่อง) | ได้ |
| ปลดล็อกดัน, รายชื่อบอสที่ฆ่า | **เซิร์ฟเวอร์** | ไม่ได้ (เว้นแต่ปลอมการฆ่าบอสข้างบน) |
| ปาร์ตี้, รอบดัน, ห้อง | **เซิร์ฟเวอร์** | ไม่ได้ |

## 2. เป้าหมาย
- เซิร์ฟเวอร์รันโลกของแต่ละ "ห้องแมพในรอบดัน" เอง: มอน, บอส, กลไกบอส, ดาเมจ, ดรอป, EXP
- เครื่องผู้เล่นส่งแค่ **อินพุต** (ทิศเดิน, ปุ่มสกิล, ทิศเล็ง) และ **วาดภาพ** + เดาล่วงหน้าเพื่อความลื่น
- กระเป๋า/EXP/ทอง เก็บที่เซิร์ฟเวอร์ (เซฟจากเครื่องเลิกใช้)

## 3. ข้อดีของโค้ดตอนนี้ (ทำไมย้ายได้)
- กฎเกมแยกจาก DOM/UI ตั้งแต่ V2 (`src/combat`, `src/status`, `src/progression`, data ใน `src/data`) — รันใน Node ได้
- `game.simulate(sec)` จำลองเกมแบบ deterministic ได้โดยไม่ต้องมีหน้าจอ (บอทและเทสต์ใช้อยู่แล้ว)
- ระบบ sync ตอนนี้ (mobSync / bossSync / ally proxy) คือรูปแบบเดียวกับที่ headless ต้องใช้: เปลี่ยน "Host = เครื่องผู้เล่น" เป็น "Host = เซิร์ฟเวอร์"

## 4. ขั้นตอน (แนะนำทำทีละขั้น แต่ละขั้นเล่นได้)
**H1 — แยก "โลกเกม" ออกจากเบราว์เซอร์**
- สร้าง `SimGame` ที่ใช้ระบบเดียวกับ `Game` แต่ไม่มี canvas / audio / UI / input (ใส่ตัวแทนเปล่า)
- ไล่หาโค้ดที่เรียก `document`, `Image`, `localStorage`, `performance`, `requestAnimationFrame` ในระบบเกม → ย้ายออกหรือใส่ตัวแทน
- Assets: เซิร์ฟเวอร์ต้องการแค่ข้อมูล (ขนาด hitbox, เวลาแอนิเมชันที่ใช้ตัดสิน hit) — แยกตัวเลขพวกนี้ออกจากรูปภาพ
- ทดสอบ: รัน `SimGame` ใน Node แล้วให้บอทเล่น A1 ได้เหมือนในเบราว์เซอร์

**H2 — เซิร์ฟเวอร์เป็น Host ของห้องแมพ**
- ทุกห้อง `<run>:<map>` มี `SimGame` ของตัวเอง (โหลดเฉพาะ grid ของแมพนั้น) ทำงาน 20-30 ครั้ง/วินาที
- ส่ง snapshot มอน/บอสแบบเดียวกับที่ Host ส่งตอนนี้ (`mobs`, `boss`, `mobAct`) → ฝั่งเครื่องผู้เล่นแทบไม่ต้องแก้ (ทุกคนเป็น "guest")
- ผู้เล่นในห้อง = ally proxy ที่เซิร์ฟเวอร์รู้จัก (มีอยู่แล้วใน mobSync)
- ห้องว่าง = ปิด `SimGame` (ประหยัด CPU)

**H3 — ดาเมจผู้เล่นตัดสินที่เซิร์ฟเวอร์**
- ผู้เล่นส่ง "ใช้สกิล X ทิศ Y" แทน "ตีโดน N ดาเมจ"
- เซิร์ฟเวอร์ตรวจคูลดาวน์ / ทรัพยากร / ระยะ แล้วคำนวณ hitbox + ดาเมจเอง (damageSystem เป็น pure อยู่แล้ว)
- เครื่องผู้เล่นเล่นแอนิเมชัน + เอฟเฟกต์ทันที (เดาล่วงหน้า) ตัวเลขดาเมจจริงมาจากเซิร์ฟเวอร์

**H4 — ตำแหน่งผู้เล่นตัดสินที่เซิร์ฟเวอร์**
- ส่งอินพุตเดิน + เลข sequence; เซิร์ฟเวอร์เดินตัวละครด้วยกฎชนกำแพงเดียวกัน
- เครื่องผู้เล่นเดินเองทันที (client prediction) แล้วแก้ตำแหน่งเมื่อเซิร์ฟเวอร์ตอบต่างไป (reconciliation)
- หลบ (dodge) / i-frame / perfect dodge ตัดสินที่เซิร์ฟเวอร์ โดยชดเชยดีเลย์ (ย้อนเวลา ~ping/2 เมื่อเช็คว่าหลบทันไหม)

**H5 — ของ / EXP / ทอง อยู่ที่เซิร์ฟเวอร์**
- กระเป๋า + อุปกรณ์ + EXP + ทอง ย้ายเข้า record ผู้เล่นบนเซิร์ฟเวอร์ (เหมือน `progress` ใน N8)
- ดรอปทอยที่เซิร์ฟเวอร์ (lootSystem เป็น pure), รอบดัน + กองของ (N9) ย้ายมาที่เซิร์ฟเวอร์ — กองของเก็บของจริงบนเซิร์ฟเวอร์
- เซฟจากเครื่องเหลือแค่การตั้งค่า (คีย์, UI)
- ร้านค้า / ตีเหล็ก / คลัง เป็นคำสั่งไปเซิร์ฟเวอร์

**H6 — บัญชีจริง**
- เปลี่ยนระบบชื่อ+token ชั่วคราวเป็นบัญชี (อีเมล/รหัสผ่าน หรือ OAuth), HTTPS + WSS, rate limit ต่อบัญชี

## 5. ประมาณภาระเซิร์ฟเวอร์ (คร่าว ๆ — ยังไม่ได้วัดจริง ต้องวัดตอน H1)
- 1 ห้องแมพ ≈ มอน 30-60 ตัว + บอส; เทียบกับที่เครื่องผู้เล่นรันตอนนี้ ~1-3 ms ต่อ tick → เครื่องเซิร์ฟเวอร์ 1 คอร์รับได้หลายสิบห้อง
- แบนด์วิดท์ต่อผู้เล่น ≈ ใกล้เคียงตอนนี้ (snapshot 15-20 ครั้ง/วินาที) ~5-15 KB/s

## 6. ความเสี่ยง
- โค้ดบางส่วนผูกกับรูป/แอนิเมชัน (เช่น จังหวะ hit ตามเฟรม) → ต้องแยกตัวเลขออกมาก่อน (H1 ใหญ่สุด)
- การเดาล่วงหน้า (prediction) ทำให้โค้ดฝั่งเครื่องซับซ้อนขึ้น — ทำเฉพาะการเดินและการหลบก่อน
- ต้องทดสอบด้วยเน็ตช้าจริง (จำลอง ping 100-200 ms)

## 7. แนะนำลำดับ
H1 → H2 (ได้ผลทันที: ไม่ขึ้นกับเน็ต Host, Host โกงมอน/บอสไม่ได้) → H5 (ของ/EXP โกงไม่ได้) → H3 → H4 → H6
