# docs/design — โฟลเดอร์ส่งมอบงานระหว่างเจ้าของ ↔ Hermes ↔ Claude Code

**Hermes กับ Claude Code มองเห็นแชทของอีกฝั่งไม่ได้** — ทุกอย่างที่ตกลงกันต้องอยู่ในไฟล์ที่นี่

## กติกา

1. ออกแบบก่อนเขียนโค้ด — สเปกต้องเขียนเป็นไฟล์ก่อนเสมอ
2. ไฟล์สเปก = สัญญา (contract). ส่งให้ Claude แค่ **พาธของไฟล์** พอ
3. ห้าม Hermes กับ Claude แก้ไฟล์เดียวกันพร้อมกัน
4. Claude เขียนโค้ด + รัน unit test เอง → Hermes ทดสอบในเกมจริง + จูนแอนแบนซ์ → อัปเดต CLAUDE.md
5. โครงสร้างของสเปก: `feature-spec-template.md` (ไฟล์นี้)
6. Always give a terminal command to run the new tests

## ไฟล์ที่มีอยู่

| ไฟล์ | คืออะไร | สถานะ |
|---|---|---|
| — | ยังไม่มี | สร้างไฟล์ใหม่เมื่อคุณพร้อม |

## ตัวอย่างคำสั่ง

คุณบอก Hermes:
```
อยากได้คลาสใหม่ธีมอักษร
```

Hermes จะ:
- อ่านคลาสที่ใกล้เคียงที่สุดก่อน (`search_files`)
- เขียน `docs/design/<ชื่อ>.md` เป็นภาษาไทย
- บอกคุณให้อ่านแก้ แล้วส่งพาธนั้นให้ Claude

Claude ทำ: `อ่าน docs/design/<ชื่อ>.md แล้วทำตาม` → เขียนโค้ด + `node tools/tests/run.mjs`

Hermes ตรวจ: เปิดเกมจริง → รัน suite → บอทไล่บอส → อัปเดต CLAUDE.md
